SETUP                                                     *fzf-pack-setup*

Supported on Neovim 0.12.6. Other stable Neovim versions 0.12 or newer are
best effort and produce a warning once per session. Prerelease/development
builds, versions below 0.12, and versions without vim.pack.get(),
vim.pack.update() or vim.system() are rejected. Build metadata alone does not
make a stable version a prerelease. Requires fzf-lua, Git and fzf.
Install through your existing plugin manager or add this checkout to
'runtimepath'. Setup is optional. Initialize |vim.pack.add()| specifications
before using the commands.
>lua
  require('fzf-pack').setup({
    concurrency = 4,       -- maximum simultaneous plugin checks
    timeout = 30000,       -- milliseconds per Git process
    max_commits = 200,     -- commits previewed per side of history
    max_log_bytes = 65536, -- history bytes per plugin and side
  })
<
Options must be positive integers. There is no startup fetching or syncing.
Each incoming and removed history is captured up to max_log_bytes, independently
of max_commits. The cap counts raw Git output bytes; section labels and visible
truncation notices are not counted. History status is classified separately,
so truncation does not change update, rollback, or diverged status.
History is collected during checks; each row's formatted preview is cached on
first display.

==============================================================================
COMMANDS                                               *fzf-pack-commands*

*:Pack*
    Browse installed plugins. Uses local refs only, without fetching. Matching
    results say "cached"; remote updates might exist. Enter simply closes.

*:PackUpdate*
    Check updates asynchronously, then open an fzf-lua picker. One plugin's
    fetch failure does not prevent others from being reviewed. Simultaneous
    checks and checks during native confirmation are refused.

*:PackCancel*
    Cancel an active :Pack or :PackUpdate check. Queued work is stopped and
    active Git processes receive SIGTERM. Canceled results do not open a picker.
    This command does not cancel native confirmation or update handoff
    validation. PackUpdate reports completed and total plugin checks.

Rows form three aligned columns: name, active/inactive state, and status.
Moving through rows updates the details pane, on the right in wide windows
and below in narrow ones. It includes the branch/tag/commit or semver constraint,
installed/target hashes, lock revision, source and path, plus incoming
and removed commit subjects and bodies. Each side is capped by max_commits and
max_log_bytes; oversized history shows a truncation notice.
Status: current, cached (local only), update, rollback, diverged, or error.
Visible status text uses the FzfPackCurrent, FzfPackUpdate, FzfPackRollback,
FzfPackDiverged, and FzfPackError highlight groups. Current defaults to green
and update to red; rollback/diverged use the warning color and errors use red.
They link to Neovim's diagnostic highlights, so the theme controls their colors.
Reopen the picker after changing colorschemes to refresh colors; cached remains
uncolored. For example, set a custom update color with:

    :lua vim.api.nvim_set_hl(0, "FzfPackUpdate", { fg = "#ff0000" })

Commit headers in incoming and removed history use the bold FzfPackCommit
highlight, whose default foreground follows Identifier. Conventional Commits
breaking changes display a [BREAKING CHANGE] warning and use bold red
FzfPackBreakingChange for the header, subject and footer explanation. Detection
recognizes type!: description, type(scope)!: description, and BREAKING CHANGE:
or BREAKING-CHANGE: footers, including indented continuation lines. Footer
highlighting stops at the next valid trailer. Override either group with:

    :lua vim.api.nvim_set_hl(0, "FzfPackCommit", { fg = "#66ccff", bold = true })
    :lua vim.api.nvim_set_hl(0, "FzfPackBreakingChange", { fg = "#ff3030", ctermfg = 9, bold = true })

Classification uses the captured subject and body. Structured Git framing shares
max_log_bytes with visible history and consumes a few bytes of that limit. A
footer beyond the limit cannot be detected; the warning is informational and
does not guarantee that omitted text contains no breaking change.

Picker keys for :PackUpdate:
    Tab / Shift-Tab    Select multiple results (standard fzf bindings).
    Enter              Review selected available changes.
    Ctrl-A             Review all available changes, even if filtered out.
    Esc                Close without applying changes.

REVIEW AND SAFETY                                        *fzf-pack-review*

Selected changes are handed to |vim.pack.update()| with offline=true in its
native confirmation buffer. Use |:write| to accept or |:quit| to cancel.
Native vim.pack owns checkouts, stashes, submodule handling, help tags, lock
updates and |PackChangedPre| / |PackChanged| events. Build hooks still work.
Restart Neovim after acceptance to use updated plugin code.

Checking fetches Git objects/refs but does not change HEAD or the lock file.
Closing either picker or native review without writing preserves versions and
lock-file bytes. The initial vim.pack call may install/repair plugins; fzf-pack
refuses inconsistent disk/lock state and asks you to initialize vim.pack first.
Changed source URLs are refused because native review can write those early.

Version semantics follow the supported 0.12.6 runtime: default origin/HEAD,
remote branches before same-named tags, tags/commits, and greatest matching
strict semver tag using |vim.version.range()|. Pinned commits remain pinned.
Installed HEAD is read from Git because vim.pack.get().rev is a locked revision
in 0.12.6. The small read-only resolver is mirrored; no private pack API is used.

Before review, HEAD and target refs are revalidated. fzf-pack also compares each
public vim.pack cached revision with the disk lock before checking and review.
If an external lock edit changes a revision, fzf-pack refuses to proceed and
leaves the file untouched; restart Neovim to reconcile vim.pack's cache.

The public API does not expose all cached metadata for active plugins, so
source/version-only cache differences cannot always be detected. The lock is
not rechecked after the native confirmation opens, so external lock edits made
during that window may be overwritten by vim.pack's native write. Concurrent
external Git processes are not locked. Git URL insteadOf aliases work when the
first raw origin URL matches the configured source; the checker reads this raw
value because git remote get-url expands aliases.

The timeout applies per checking Git process, not to native acceptance/hooks.
Interactive Git credential prompts are disabled during checking. Normal Git
config and credential helpers apply. Submodules are handled on native acceptance,
not recursively fetched by the checker.

PackCancel signals the direct Git process; it does not guarantee termination of
the entire transport process tree. A transport child may keep inherited pipes
open after Git exits. Its late result is ignored, and a new check can start while
those pipes drain.

Real-PTY CI is configured for Linux with supported Neovim 0.12.6 and
fzf 0.74.5. macOS behavior is not verified by CI.
It targets the current fzf-lua snapshot
(48d7c3db291a2c7c1825905c227a6bc81c83b837) and an older 0.7 compatibility
snapshot (47b85a25c0c0b2c20b4e75199ed01bb71e7814f5). The older ref is additional
compatibility coverage and does not change the Neovim support contract.

Future milestones: lock-file sync review, optional early startup synchronization
(disabled by default), and inactive-plugin cleanup review. Not implemented yet.
